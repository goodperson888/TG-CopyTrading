# TG 群跟单 · 本机控制台

2026-11-15，当前版本 **0.2.0**。形式为本机后台程序＋浏览器控制台，两个交易模式共用策略，账本分别保存。

**当前状态：自动监听、纸上交易、离线演练可用；实盘接入代码和异常流程已实现，尚未使用本人的已登录钱包完成端到端验收。** 2026-11-15，本机已加载本人开发者 API 凭证，SOL 和 BSC 真实只读报价均通过；没有登录跟单钱包或执行真实交易。策略参数仍待补齐，新买入保持暂停。只读报价和模拟接口测试不能代替真实账户的交易权限、费用、签名和成交回执验收。

## Windows 下载与打包

GitHub **Actions → Windows portable build** 自动生成 Windows 10 / 11 x64 便携包，内置 Node.js 和 OKX 钱包组件。解压后双击 `配置.cmd` 填写本机 `.env`，保存后运行 `启动.cmd`；`停止.cmd` 正常停止后台。详见 [Windows 使用说明](WINDOWS.md)。通用包及仓库均不含个人 Key、钱包会话、策略快照或交易数据库。

开发机可用 `npm run build:win` 构建通用包；本人需要预填配置时可用 `npm run build:win:private`，结果只保存在被 Git 忽略的 `private-builds`，包含本人 `.env` 及策略设置，**不可公开上传或转发**。配置版不迁移钱包会话、订单或持仓，Windows 首次默认纸上暂停。GitHub Actions 禁止生成带本机凭证的包。

## 使用方式

需要 Node.js 24+。Finder 双击 `启动.command`，程序自动监听 `@WoniuTuGou` 并打开控制台。启动时现有消息只归档，新买入默认暂停。填好规则、检查连接后，点“启动纸上跟单”或“启动实盘跟单”。

后台运行不依赖控制台标签页，关闭标签仍继续监听和检查已有持仓。终端程序需保持运行。macOS 主程序使用 `caffeinate -i -w` 防止空闲睡眠；合盖、手动睡眠、断网或停止程序仍会中断检查。没有安装开机自启或后台系统服务。重启后自动恢复监听和已有持仓检查，新买入仍需手动启动。

完全停止：双击 `停止.command`，或在启动终端按 `Ctrl+C`。停止脚本只向当前用户、本项目目录中的 `node src/server.mjs` 后台发送正常退出信号，等待最多 15 秒，不强杀其他 Node 项目。**完全停止也会停止已有持仓的止盈止损检查，不自动清仓。** 页面“暂停新买入”只停新买单；“停止监听”只停消息读取和新买入，两者均继续检查已有持仓退出。配置 Key 的操作步骤见 `Key申请与停止说明.md`。

```sh
npm ci --ignore-scripts
npm start
```

控制台为 `http://127.0.0.1:8765`，仅本机可访问。同一数据目录由 SQLite 的独占文件锁限制为一个执行实例；进程退出或崩溃会释放锁。不要在运行时删除 `data/run-lock.sqlite`。

## 两个模式

| 项目 | 纸上交易 | 实盘交易 |
|---|---|---|
| 消息 | 自动读取公开频道新消息 | 同左 |
| 策略 | 首推、去重、预算、追价、止盈止损等 | 同左 |
| 钱包 | 无需钱包，使用开发者 API 报价 | 独立 OKX Agentic Wallet 自动签名 |
| 成交 | 真实报价扣设定滑点后的保守模拟 | 链上最终确认的实际资产变化 |
| 均价 | 模拟支出÷模拟到账数量 | 实际计价币支出÷实际到账数量 |
| 资金记录 | 独立纸上账本 | 独立实盘账本 |

保存策略或切换模式会暂停新买入。已有纸上和实盘持仓均按建仓规则继续检查退出，切换模式不会清掉实盘仓位或把纸上仓位变为实盘。记录视图可单独切换，不影响执行模式。

“离线演练”是测试工具，使用 20 条历史公开消息＋合成报价，每轮单独保存。无需 API 或钱包。不是第三个交易模式，也不是收益回测。可测试止盈、止损和卖出受阻；未平演练仓需处理完才能开始新一轮。

## 首次接入

纸上交易：本机已配置 `.env`；新安装时若不存在，可复制 `.env.example` 为 `.env`。在本机填写本人 OKX 开发者 `OKX_API_KEY`、`OKX_API_SECRET`、`OKX_API_PASSPHRASE`，按账户要求填写 `OKX_PROJECT_ID`，设文件权限为 0600，再重启。填写策略后直接点“启动纸上跟单”，程序自动验证 SOL / BSC 报价，不需要手动输入测试地址。API 凭证不发到浏览器，不需要连接钱包。“高级诊断”默认折叠，仅排查连接时使用。

实盘：官方工具 **OnchainOS 4.6.10** 已安装在项目 `.tools/onchainos`，按官方 checksums 校验了 SHA-256。需要重新安装时双击 `安装钱包组件.command`。安装器固定版本和哈希，不安装全局 CLI、其他技能或系统服务。

实盘模式在“策略与连接”点“连接独立钱包”，打开官方页面完成登录，本机会自动获取结果。此步骤可能创建官方钱包账户，由用户主动点击触发。连接、设置限额并保存策略后直接点“启动实盘跟单”，程序自动刷新钱包、检查限额和支持网络的只读报价，再允许新买入。未通过或检查中点击取消/暂停，均保持暂停；不产生测试交易。程序不会自动登录、导入主钱包、索要私钥或助记词。普通 OKX 插件钱包的 connect 不提供无人值守签名，本程序使用官方 Agentic Wallet。

使用专门的跟单账户，在官方钱包页面设置单笔及每日交易限额；需要允许自动交易。程序读取真实 policy 标志：未设置、无法读取、仍需逐笔确认时，不能启动自动实盘。官方限额也可能限制卖出，请为完整退出保留相应权限和额度。程序不会自动更改官方策略。

SOL 需 USDC 和 SOL，BSC 需 USDT 和 BNB。BSC 当前只使用已有授权，检查输入币及买入后代币的退出授权；任一路由授权不足则跳过新买入。程序不自动授予无限授权。行情路由、合约风险或持仓可卖性以后仍可能变化。

API 报价凭证和钱包登录是不同权限。无开发者凭证时，已登录官方 CLI 也可尝试读取报价，但取决于实际账户授权。本机只读测试确认：未登录且没有凭证时返回 `50114 Invalid Authority`，不能把“安装工具”当作“已有免费行情权限”。

**未验证永久免费或未来套餐权益。** 报价成功只证明当前请求可用，不代表长期费用、交易权限、账户地区或额度已验收。官方当前规则及本人的实际账户为准，不自动购买套餐或用真实交易探测权限。

## 策略和资金口径

- 当前识别和路由支持 SOL、BSC；其他链、地址冲突、格式不明、无有效路由均跳过。币名不设白名单。
- 公链＋完整合约地址去重。只尝试首次发现的新币首推；跟踪、日报、编辑、过期消息、启动历史消息不补买。首次跳过后不因重复首推再次尝试。
- 用户填写所有资金、涨跌和成本参数。程序不预设金额；U 是计价稳定币单位，SOL 用 USDC，BSC 用 USDT。计价稳定币偏离 1 美元超过 2% 时停止该次建仓或退出。
- 两个账本分别累计本金和网络费用；卖出不释放累计投入额度。实盘未决买单按本金＋用户网络费上限预留，另占持仓数量；未核对订单阻止新的实盘买入。失败链上交易的网络费计入累计费用。
- 纸上数量按报价减设定滑点、向下取整数；实盘向官方请求固定滑点的待签交易，不使用自动放宽滑点、`--force` 或无限授权。
- 买入前验证买入和反向卖出报价。实盘进一步生成待签 Swap，核验同一待签交易的资产、输入金额、追价、价格影响、预估网络费、风险和交易扫描后，交给官方钱包签名。不会使用一键 execute 重新报价并跳过本机检查。
- 止盈止损相对各仓入场均价，全卖本策略数量。实盘等待 Solana finalized 或 BSC 至少三块确认，按钱包 token delta / Transfer 日志核对成交，禁止用报价输出数量代替实际到账。网络费按实际原生币消耗和预检时的原生币美元价格折算，不是成交时精确美元汇率。
- **网络费上限是预估检查，不是对最终扣款的绝对保证。** 余额、Gas、价格、路由可能变化。实盘实际数量或费用偏离预检边界时，如实入账并暂停新买入。纸上也不能复现全部平台费用、税费、网络延迟和链上执行偏差。
- 持仓保留建仓策略快照。触发后退出条件锁定；卖出受阻保留持仓，按原限制有限重试，达到次数上限后需在页面处理。暂停新买入不停止已有持仓退出。

## 订单恢复

实盘签名前持久化订单；提交后只标记待确认，不立即建立持仓或显示卖出成功。结果不明、请求超时、程序在提交时中断，都暂停新买入并保留预算。后台只查原交易，不自动重新广播。卖单待确认期间保留原数量，禁止重复卖出。

有哈希时，后台通过 RPC 查询最终回执。无哈希时，在官方钱包核对原订单，等最终确认后到“操作记录”关联原交易哈希。程序校验链、钱包、交易时间、方向及数量。完全没有广播的未知结果不会自动解除；需人工核对后处理，不能靠盲目重发恢复运行。

回执不匹配、只成交部分数量或缺少可靠数据时，保留待核对记录并停止新买入，不猜测成交、不标记卖完。当前只在页面及本机日志提示，没有离线推送。因此“启动后按规则运行”不等于任何异常都无需处理。

## 本机数据和网络

`data/desk.sqlite` 保存设置、消息、编辑、两个账本及订单日志。`data/agent-wallet` 是此项目的官方 CLI 数据目录，采用官方加密文件凭证存储，与全局 CLI 账户分开。**其中会保存可用于自动交易的敏感登录会话及加密身份文件**，不能上传、共享或提交版本库。目录 0700，数据库及敏感文件 0600，进程 umask 0077。应用不接收钱包私钥或助记词。

读取公开预览 `https://t.me/s/WoniuTuGou`，不提取 Telegram 浏览器会话。macOS 读取既有系统 HTTPS 代理，不修改系统设置。`.env` 的 `OUTBOUND_PROXY=direct` 可强制直连，也可指定 HTTP CONNECT 代理。默认报价请求间隔至少 1.2 秒，公开消息轮询 20 秒；多持仓、网络慢或签名请求会拉长检查周期。不是毫秒级跟单。

公开预览可能缓存、延迟或只提供有限窗口，无法保证完整实时。发现窗口断档就暂停新买入并归档现有窗口。持续采样尚待验证。需要更强完整性时，可另行接入专用 Telegram 账号的官方 API。

可配置自有 `SOLANA_RPC_URL` / `BSC_RPC_URL` 提升回执可用性。默认公共 RPC 可能限流。控制台只允许本机 Host / Origin，并要求随机令牌；不开放 CORS，静态资源固定白名单。近期导出各最多 200 条、日志 100 条，完整记录仍在 SQLite，导出不是完整备份。
